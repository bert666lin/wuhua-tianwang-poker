# 全链路体验优化设计

## 目标

在不更换紫金视觉风格、不修改核心牌规的前提下，降低大厅选择成本，释放手机横屏牌桌空间，增强匹配与结算反馈，并让后台在用户量增长后仍可操作。

## 已确认范围

1. 牌桌：手机横屏收紧真实比分栏，以“主花色、庄分、闲分”为首要信息，完整名称在宽屏保留；保留多张牌全屏查看与收起结算后的下一局入口。开发预览器的阶段切换条不属于正式牌桌，不纳入产品改造。
2. 大厅：快速开始成为唯一主操作；建房、加入房间、房间列表归为好友房次级入口；弱化未开放比赛场和低频运营入口。
3. 匹配：现阶段没有真人匹配服务，因此如实显示正在安排电脑对手，并允许跳过展示动画直接开局；取消流程保持可恢复。
4. 结算：首屏优先展示输赢、升降级、金币与下一局；牌面证据和房间累计结果保留在下方。
5. 后台：注册用户、游客、AI 使用明确标签；玩家列表提供身份/状态筛选和分页，房间参与者继续显示用户 ID 与用户名。
6. 质量保障：视觉截图补齐牌桌状态、结算和后台；新增一条覆盖大厅到下一局关键按钮状态的 UI 冒烟检查。

## 约束

- 玩家端整个扑克牌 App 以手机横屏为主要设计与验收基准；牌桌竖屏只展示旋转引导，其他页面竖屏仅保证可用。后台是独立运营网页，可保留竖屏适配。
- 不引入新的前端框架或重量级 UI 依赖。
- 不伪装 AI 为真人。
- 所有禁用按钮必须同时给出可理解的原因或状态文字。
- 保持现有线上路由、房间协议和结算数据结构兼容。
- 短信验证码与登录限流属于独立安全项目，本轮仅保留测试阶段提示，不假接第三方短信服务。

## 验收标准

- 390×844、844×390、1440×900 三种视口无主按钮遮挡或横向溢出。
- 玩家进入大厅后能在首屏明确找到快速开始、建房和加入房间。
- 匹配、出牌、结算、收起结算、下一局每个状态都有明确且可点击的主操作。
- 后台可按用户 ID/用户名搜索，并能筛选身份与翻页。
- 客户端、服务端测试和构建全部通过；发布后首页、静态资源、健康接口、房间接口和游客登录通过。
- 发布前保留 Git、线上前端、线上后端和 SQLite 数据库备份，并校验数据库完整性。
